# Сдача задачи

Правила — [CLAUDE.md](../../../CLAUDE.md), «Сборка и проверка» и «Ветки и PR». Здесь — порядок.

## 1. Перед показом

1. Сделано всё, что согласовано с владельцем, а не часть. Разбить работу на этапы можно,
   только если владелец на это согласился.
2. Документация в том же изменении: шаг в справке (CLAUDE.md, «Когда обновлять справку»), README,
   `docs/development.md`, ADR (решение, о котором владелец не просил, —
   со статусом «Предложено»), KDoc правил одного экрана.
3. Вид поменялся намеренно — `scripts/dev.sh goldens`, закоммить изменившиеся PNG, не открывая их.
4. `git fetch`, затем `scripts/dev.sh check` — зелёный. После fetch `rules` сверяет номера
   новых ADR с ветками параллельных сессий; совпал — по [шаблону ADR](../../../docs/adr/template.md).

## 2. Показ

1. `scripts/dev.sh run` из своего worktree — на эмулятор, где смотрит владелец. Сборка
   встанет поверх debug-сборки параллельной сессии: та пересоберёт свою, когда понадобится.
2. Скажи коротко: что поменялось, где это найти (экран, действие), на что посмотреть. Нужен
   дневник с историей — `/seed`.
3. Жди «да». Замечания — правка, снова `check` и `run`.

## 3. PR

1. Коммиты — по-русски, по смыслу изменения; `git push -u origin <ветка>`.
2. Описание — в файле в scratchpad, по образцу ниже:
   `gh pr create --base main --title "<что изменилось>" --body-file <файл>`.
3. Описание меняй целиком из файла: `gh api -X PATCH repos/hiraise/Babylog/pulls/<N> -F body=@<файл>`.

```markdown
<Одна-две фразы: что теперь может пользователь или разработчик.>

## Что меняется для пользователя

- <по пункту на заметное изменение; ссылки на ADR>

<ADR: какой добавлен или почему не нужен. README обновлён — если обновлён.>

## Проверка

- `scripts/dev.sh check` зелёный; <какие тесты и эталоны добавлены или изменились>.
- Владелец проверил сборку на эмуляторе и одобрил.

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

## 4. CI и дальше

1. `gh pr checks <N> --watch` — в фоне. Упало — `gh run view <id> --log-failed`, повтори шаг
   локально (`scripts/dev.sh rules|build|schemas`), исправь, запушь.
2. Скажи владельцу ссылку на PR и итог CI. Сливает PR он.
3. Есть открытый релиз (PR из ветки `release/v…` в `gh pr list`) и владелец просит включить задачу —
   влей её туда по скиллу `/release`, раздел «Пока PR открыт».
