# ADR-0034: Зависимости сборки проверяются по SHA-256 из `gradle/verification-metadata.xml`

- **Статус:** Принято
- **Дата:** 2026-10-19
- **Затрагивает:** зависимости и плагины в `*.gradle.kts`, `gradle/verification-metadata.xml`, `scripts/dev.sh deps`, `.github/dependabot.yml`

## Контекст

Подписанный релиз собирается в CI из того, что Gradle скачал из Maven Central, Google Maven и Gradle
Plugin Portal ([ADR-0012](0012-release-signing.md)). Подменённый там артефакт попал бы в APK под ключом
проекта, а контрольная сумма проверялась только у дистрибутива Gradle.

## Решение

- Держи в репозитории `gradle/verification-metadata.xml`: Gradle сверяет SHA-256 каждого артефакта и его
  метаданных (`verify-metadata`) в любой сборке — локальной, в CI и в релизе.
- Новая зависимость, плагин или версия — в том же изменении выполни `scripts/dev.sh deps` и закоммить
  изменившийся файл вместе с `*.gradle.kts`. Руками суммы не правь.
- `deps` пишет файл заново по задачам CI; у `aapt2` свой файл для каждой ОС — суммы для Linux (это CI)
  и Windows `deps` берёт с Google Maven.
- Без суммы доверяй только `-sources.jar` и `-javadoc.jar`: их скачивает IDE для показа, в сборку они
  не входят. Другие `<trust>` и `--dependency-verification lenient|off` не добавляй.
- «Dependency verification failed» без смены версий — признак подмены, а не повод перезаписать суммы:
  сначала сравни артефакт с опубликованным.
- Подписи PGP (`verify-signatures`) не проверяй: ключи пришлось бы вести вручную, а на Google Maven
  подписей у артефактов нет.

## Последствия

- PR Dependabot по Gradle падает на проверке, пока в его ветке не выполнят `scripts/dev.sh deps`
  и не закоммитят файл.
- `deps` прогоняет сборку с тестами — пара минут на каждое обновление.

## Проверка

- Gradle сверяет суммы сам; `scripts/dev.sh rules`: файл есть, `verify-metadata` включён, лишних `<trust>` нет.

## Альтернативы

- Проверять только артефакты, без `.pom` и `.module`: подменённые метаданные подтянули бы чужую зависимость.
- Доверять `aapt2` без суммы, чтобы не возиться с ОС: это исполняемый файл сборки, его подмена опаснее прочих.
