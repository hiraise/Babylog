# ADR-0044: Тёмная тема по умолчанию — «Классика»

- **Статус:** Принято
- **Дата:** 2026-10-22
- **Затрагивает:** `DarkPalette.DEFAULT` в `ThemeModeStore.kt`, `values-night/colors.xml` (`window_background`, `shade_*`), тёмные эталоны в `app/src/test/screenshots/` и `docs/screenshots/`
- **Заменяет:** пункт [ADR-0032](0032-dark-palettes.md) о палитре по умолчанию

## Контекст

С 1.7 тёмная тема по умолчанию — спокойные «Сумерки». Владелец решил, что по умолчанию лучше прежняя
зелёная «Классика» — с ней приложение и на скриншотах README. Остальные палитры остаются на выбор.

## Решение

- Палитра тёмной темы по умолчанию — «Классика»: `DarkPalette.DEFAULT = CLASSIC`.
- `window_background` и цвета уведомления в шторке (`shade_*`) в `values-night/colors.xml` — роли
  «Классики» (`ClassicDarkColors`): ресурсы повторяют палитру по умолчанию, как требует ADR-0032.
- Порядок палитр в листе «Тема» не меняй: «Классика» остаётся последней.

## Последствия

- Кто палитру не выбирал, после обновления увидит «Классику» вместо «Сумерек»; выбранная палитра
  сохраняется.
- Заставка холодного запуска при другой палитре мелькает фоном «Классики».

## Проверка

- `ThemeWindowTest`: ресурсы `values-night` совпадают с палитрой по умолчанию; эталон `diary_day_dark` —
  «Классика», остальные палитры — `diary_day_dark_<палитра>`.
