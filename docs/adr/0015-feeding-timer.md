# ADR-0015: Кормление — таймер с началом и концом; идущее кормление — `Feeding` с `end = null`

- **Статус:** Принято
- **Дата:** 2026-10-16
- **Затрагивает:** `core/model/BabyEvent.kt`, `core/model/EventRecord.kt`, `core/data/` (`startFeeding`), `core/data/room/Migrations.kt`, `app/schemas/`, `feature/diary/`, `feature/editor/FeedingSheets.kt`, `feature/summary/DaySummary.kt`, `feature/transfer/CsvTransfer.kt`, README «Возможности» и «Формат CSV»

## Контекст

Кормление было мгновенной записью с выбором груди. Владельцу нужно, как у сна, «начать — закончить»:
длительность и смена груди посреди кормления. Колонка `endTime` в `events` уже есть
([ADR-0008](0008-data-model-children.md)), но у всех прежних кормлений она пуста.

## Решение

- `Feeding.end` — конец кормления, `null` — кормление идёт. У ребёнка не больше одного идущего
  кормления (`DiaryRepository.startFeeding` в транзакции); с идущим сном оно не связано.
- Одна запись — одна грудь. «Сменить грудь» в одной транзакции закрывает идущее кормление и
  с той же секунды начинает новое другой грудью (`DiaryViewModel.switchBreast`).
- Кормление в сводке — сессия: запись, начатая ровно в конце предыдущей, — её продолжение
  (`feedingSessions`). «Последнее … назад» считается от начала сессии, грудь — последняя в ней.
- Прежние кормления — без длительности: миграция 3→4 ставит им `endTime = startTime`. История
  показывает у такой записи только время начала.
- В CSV `end` у `FEEDING` — конец кормления. `FEEDING` без `end` (файлы до этого ADR) импортируй
  с `end = start`, а не идущим таймером; если такое же идущее кормление уже есть в базе — это дубликат.
- Кормление начинай на карточке главного экрана (`FeedingCard`), как сон; плитки «Кормление»
  в быстрых действиях нет. Карточки таймеров — `TimerStartCard` и `RunningTimerCard`
  из `core/ui/components/`.

## Последствия

- При смене груди в истории две записи: «левая · 10 мин», «правая · 5 мин»; в сводке — одно кормление.
- Идущее кормление в экспорте — без `end`: на другом телефоне оно станет кормлением без длительности.
- Новый таймер (например, сцеживание) делается так же: запись с `end = null`, метод `startXxx`
  в репозитории и карточки из `TimerCard.kt`.

## Проверка

- `MigrationTest` (3→4), `RoomDiaryRepositoryTest`, `DiaryViewModelTest` (смена груди),
  `DaySummaryTest` (сессии), `CsvImportTest` (`FEEDING` без `end`), скриншот `diary_feeding.png`.

## Альтернативы

- Время каждой груди в одной записи — новый формат детали и CSV; запись на грудь проще.
- Идущее кормление вне базы — у сна таймер в базе (ADR-0008), два способа путали бы.
- Оставить прежним кормлениям `end = null`, а идущее отмечать флагом — нужна новая колонка.
