# ADR-0005: CSV — формат экспорта и импорта: обратная совместимость, импорт только добавляет

- **Статус:** Заменено [ADR-0009](0009-csv-with-children.md)
- **Дата:** 2026-08-15 (записано 2026-10-15)
- **Затрагивает:** `data/CsvCodec.kt`, `MainViewModel.exportCsv`/`importCsv`, `CsvCodecTest`, README «Формат CSV»

## Контекст

Облачного автобэкапа нет ([ADR-0002](0002-standalone-local-data.md)), поэтому перенос
данных на другой телефон и резервная копия — это файл, который пользователь сохраняет
сам. Файл должен открываться в Excel и других таблицах.

## Решение

- Формат: заголовок `type,start,end,detail,note`; время локальное, `yyyy-MM-dd HH:mm:ss`;
  экранирование по RFC 4180; UTF-8 с BOM, строки через CRLF; служебная строка `PROFILE`
  хранит дату рождения в `start`. Описание для пользователя — README «Формат CSV».
- Файл, экспортированный любой прежней версией, импортируется новой. Колонки
  не удаляются, не переименовываются и не переставляются; новые добавляются только
  в конец и не обязательны при импорте.
- Импорт — слияние: он ничего не удаляет и не перезаписывает и выполняется в одной
  транзакции:
  - запись, совпадающая с существующей во всех полях, пропускается как дубликат;
  - `SLEEP` без `end` пропускается, иначе появится «фантомный» активный таймер;
  - дата рождения из файла применяется, только если в профиле её нет;
  - некорректная строка считается ошибкой и пропускается, импорт продолжается.
- Любое изменение формата — с тестом в `CsvCodecTest` и правкой README.

## Последствия

- Часовой пояс в файле не хранится: на устройстве с другим поясом записи сохранят
  «настенное» время, а не исходный момент.
- Дедупликация опирается на секундную точность времени ([ADR-0004](0004-data-model.md)).
