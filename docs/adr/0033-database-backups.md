# ADR-0033: Повреждённая база не удаляется — она откладывается, а дневник восстанавливается из ежедневной копии в `no_backup/`

- **Статус:** Принято
- **Дата:** 2026-10-19
- **Затрагивает:** `AppDatabase.build`, `core/data/room/` (`SafeOpenHelperFactory`, `DatabaseBackups`), `RecoveryNotices`, `DatabaseRecoveredSheet`, `AndroidManifest.xml` (`allowBackup`, правила переноса данных)
- **Заменяет:** пункт «Последствий» [ADR-0002](0002-standalone-local-data.md) о переносе данных

## Контекст

Обработчик Android по умолчанию удаляет файл базы, как только SQLite сообщит о повреждении — даже
одной страницы. Других копий нет: автобэкап выключен ([ADR-0002](0002-standalone-local-data.md)), CSV
пользователь делает сам и без фото. Сбой памяти или выключение посреди записи стирали весь дневник.

## Решение

- Открывай базу только через `AppDatabase.build` с `SafeOpenHelperFactory`. `fallbackToDestructiveMigration`
  не включай: неудачная миграция не должна стирать дневник.
- При повреждении (`onCorruption`) не удаляй файлы базы (`babylog.db`, `-wal`, `-shm`, `-journal`):
  перенеси их в `no_backup/db-corrupted/<время>/` (хранится последний случай) и положи на место свежую
  копию. Без копии Room создаёт пустую базу.
- Копию делай раз в сутки, при первом открытии базы процессом: файлы копируются до открытия, а в фоне
  снимок сводится в один файл и проверяется `PRAGMA quick_check`. Не прошёл проверку — удаляется, прежние
  копии остаются.
- Храни две последние проверенные копии: `no_backup/db-backups/babylog-<millis>.db`. Если свободно меньше
  размера базы плюс 100 МБ, копию пропусти: память, заполненная копией, сломала бы запись в дневник.
- Копии и отложенные файлы — только в `noBackupFilesDir`: они не уходят ни в облако, ни при переносе на
  новый телефон, сеть им не нужна.
- О восстановлении сообщай листом `DatabaseRecoveredSheet`, а не снекбаром: время копии и «Импорт из CSV».
  Сообщение хранит `RecoveryNotices`, пока его не закроют, — и после перезапуска.
- Перенос между телефонами средствами Android (D2D, Android 12+) не запрещай: `allowBackup="false"`
  выключает только облачный бэкап, а D2D переносит базу вместе с фото.

## Последствия

- Копии занимают до двух размеров базы; основная часть — фото записей.
- Восстановление теряет записи после последней копии: их вернёт импорт свежего CSV, дубликаты он пропустит.
- Процесс, который живёт дольше суток, новую копию сделает при следующем запуске.

## Проверка

- `DatabaseBackupsTest`, `RecoverySheetTest`; `scripts/dev.sh rules`: `SafeOpenHelperFactory` в `AppDatabase.kt`,
  нет `fallbackToDestructiveMigration`.

## Альтернативы

- Копия в CSV — без фото, а восстановление из неё дольше.
- `VACUUM INTO` — только с SQLite 3.27 (Android 11), а minSdk 26.
- Копия SQL-запросами при открытой базе — Android начинает транзакцию с `BEGIN EXCLUSIVE`: запись
  в дневник ждала бы конца копии.
- Копия в папку пользователя (SAF) или в облако — интеграция со своим ADR ([ADR-0002](0002-standalone-local-data.md)).
