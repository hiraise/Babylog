# ADR-0012: Релизы — APK, подписанный ключом проекта в CI, публикуется в GitHub Releases по тегу `v<versionName>`

- **Статус:** Принято
- **Дата:** 2026-10-16
- **Затрагивает:** `app/build.gradle.kts` (`signingConfigs`, `versionCode`, `versionName`, `dependenciesInfo`), `.github/workflows/release.yml`, `scripts/dev.sh release`, README «Установка на телефон» и «Сборка»

## Контекст

Release раньше подписывался debug-ключом машины владельца: ключ жил на одном компьютере
с общеизвестным паролем, а на раннере CI каждый раз создавался бы новый, и APK из CI не
вставали бы поверх установленного приложения.

## Решение

- Подписывай релизы одним ключом проекта: PKCS12, alias `babylog`. Отпечаток SHA-256
  сертификата — `RELEASE_CERT_SHA256` в `scripts/dev.sh`; тот же отпечаток — в README.
- Храни ключ и пароль только в секретах окружения `release` на GitHub
  (`BABYLOG_KEYSTORE_BASE64`, `BABYLOG_KEYSTORE_PASSWORD`) и в резервной копии владельца.
  В репозиторий их не клади ([ADR-0001](0001-open-source-non-commercial.md)).
- Окружение `release` выдаёт секреты только тегам `v*`. Проверочный workflow секретов не
  получает ([ADR-0011](0011-ci-github-actions.md)).
- Без ключа `assembleRelease` собирает неподписанный APK. Не подписывай release debug-ключом.
- Выпускай релиз так: PR поднимает `versionCode` на 1 и меняет `versionName`; после слияния
  на этот коммит `main` ставится тег `v<versionName>`. `.github/workflows/release.yml` через
  `scripts/dev.sh release` сверяет тег с версией, собирает APK, проверяет отпечаток подписи
  и создаёт GitHub Release с APK и `.sha256`.
- Тег и релиз создаёт владелец или агент по его просьбе.
- Не включай в APK блок метаданных зависимостей (`dependenciesInfo`): он зашифрован ключом Google.
- Смену ключа оформляй новым ADR: установленные копии примут её только через переустановку.

## Последствия

- Пользователи ставят APK из Releases и обновляются поверх. Сборки, подписанные debug-ключом,
  один раз переустанавливаются: экспорт CSV → удаление → установка → импорт.
- Потеря ключа — конец обновлений поверх установленного: резервная копия у владельца обязательна.
- Подключение F-Droid позже не потребует менять сборку: закрытых блоков в APK нет.

## Проверка

- `scripts/dev.sh release v<versionName>` падает, если тег не совпадает с `versionName`,
  ключа нет или APK подписан не ключом проекта.
- В `app/build.gradle.kts` нет `signingConfigs.getByName("debug")`.

## Альтернативы

- Debug-ключ владельца — привязан к одной машине, пароль общеизвестен.
- Google Play и Play App Signing — закрытый сервис, противоречит духу ADR-0001.
- F-Droid сейчас — отдельный процесс публикации ради одного пользователя; отложен.
