# ADR-0045: Экспорт — архив .zip с CSV и фото; импорт принимает архив и CSV и только добавляет

- **Статус:** Принято
- **Дата:** 2026-10-22
- **Затрагивает:** `feature/transfer/` (`DiaryArchive.kt`, `CsvTransfer.kt`, `CsvCodec.kt`, `DocumentStore`), `DiaryRepository` (`photoIds`, `photoJpeg`, `addEventPhoto`), пункты меню ⋮ и выбор файла в `DiaryScreen.kt`, `DatabaseRecoveredSheet`, `docs/development.md` «Формат экспорта»
- **Заменяет:** пункт [ADR-0009](0009-csv-with-children.md) об экспорте в CSV, пункт [ADR-0024](0024-event-photos.md) о том, что фото не входят в CSV; пункт ADR-0023 о том же — в сводном [ADR-0046](0046-child-photo.md)

## Контекст

CSV переносил записи без фото: на новом телефоне заметка «см. фото» оставалась без фото, а фото ребёнка
ставили заново. С фото дневник переносил только системный перенос Android 12+.

## Решение

- Экспорт — один архив `baby-diary-<дата>.zip` (⋮ → «Экспорт в файл»): первым `diary.csv` по
  [ADR-0009](0009-csv-with-children.md), затем фото в `photos/`. Экспорта «только CSV» нет: CSV достают из архива.
- Строку CSV с фото связывает последняя колонка `photos`: пути файлов в архиве через `;`, по порядку. У `PROFILE` —
  фото ребёнка, у записи — её фото.
- Имена файлов — только ASCII: фото записи `photos/<yyyy-MM-dd_HH-mm-ss>_<n>.jpg` по её началу, фото ребёнка
  `photos/child_<n>.jpg`. Кириллицу в имена не пиши: её понимают не все распаковщики.
- Экспорт читает фото из базы по одному (`photoIds`, `photoJpeg`) и пишет потоком: дневник с фото в память не
  помещается. Дети, записи и список фото — одной транзакцией, сами фото — после неё. JPEG — без сжатия (`STORED`).
- Импорт — один пункт «Импорт из файла»: архив узнаётся по сигнатуре `PK`, иначе файл — CSV. Архив читается
  дважды, сначала `diary.csv` (он может лежать в папке — пути фото считаются от неё), затем фото; копию на диск
  не делай.
- Импорт архива — одна транзакция вместе с фото: архив, который не дочитался, не меняет дневник.
- Фото встаёт к записи, которую импорт добавил, и к записи-дубликату, если у неё своих фото нет: так архив
  возвращает фото записям, перенесённым раньше через CSV. К записи с фото не добавляй ничего.
- Фото ребёнка ставь, только если у него своего нет — как дату рождения и пол.
- Файл больше `EventPhoto.MAX_BYTES`, не JPEG или не найденный в архиве — фото не загружено, запись остаётся.
  CSV без архива фото не загружает; итог импорта советует выбрать архив.

## Последствия

- Версии до 1.10 архив не откроют, а `diary.csv` из него примут: колонку `photos` они пропускают.
- Архив большой — фото по 0,3–1,2 МБ, — и, как CSV, не зашифрован.
- Обновляя фото записи или ребёнка, помни о колонке `photos`: файл должен попасть в архив.

## Проверка

- `DiaryArchiveTest`, `DiaryArchiveRoomTest` (оборванный архив не меняет базу), `TransferMenuTest`, `CsvCodecTest`.

## Альтернативы

- Фото в CSV текстом (base64) — Excel не открывает ячейку длиннее 32 767 символов, а фото — сотни тысяч.
- Папка вместо архива — её не переслать одним файлом.
- Копия базы (`.db`) — восстановление заменяет дневник, а не сливает; файл не открыть ничем, кроме приложения.
- Второй пункт «только CSV» — владелец отказался: CSV есть в архиве.
