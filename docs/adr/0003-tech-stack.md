# ADR-0003: Стек: Kotlin, Jetpack Compose и Room в одном модуле, минимум зависимостей

- **Статус:** Заменено [ADR-0006](0006-tech-stack-agp9.md)
- **Дата:** 2026-08-15 (записано 2026-10-15)
- **Затрагивает:** `build.gradle.kts`, `app/build.gradle.kts`, `settings.gradle.kts`; структура пакетов `com.kid.babylog`

## Контекст

Приложение небольшое, и пишут его AI-агенты: чем меньше библиотек и слоёв, тем меньше
контекста нужно для изменения и тем меньше мест для ошибок.

## Решение

- Язык — Kotlin. UI — Jetpack Compose (Material 3) без XML-разметки экранов; одна `MainActivity`.
- Данные — Room (через KSP) поверх SQLite; модель данных — [ADR-0004](0004-data-model.md).
- Состояние — `AndroidViewModel` и Kotlin Flow. Зависимости собираются вручную через `App`,
  без DI-фреймворков.
- Один Gradle-модуль `:app`. В корне пакета — `App`, `MainActivity`, `MainViewModel`;
  `data/` — сущности, DAO, база, CSV; `ui/` — экраны, диалоги, форматирование.
- minSdk 26 (Android 8.0), compileSdk и targetSdk 34, JDK 17.
- Новую библиотеку подключай, только если без неё задачу разумно не решить, и вместе с ADR.
  Обновление версий без изменения поведения ADR не требует.
- Debug-сборка — отдельное приложение (`applicationIdSuffix = ".debug"`) со своей базой:
  отладка не трогает настоящие записи.

## Последствия

- Навигационной библиотеки, DI-фреймворка, сетевого стека и многомодульности нет
  сознательно; их появление — повод для нового ADR.
