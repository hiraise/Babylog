# Дневник малыша

Открытое Android-приложение для отслеживания режима ребёнка. Все данные хранятся
только локально на устройстве (SQLite/Room). Сейчас у приложения **нет permission
INTERNET** — оно физически не может выйти в сеть. Нет рекламы, биллинга и
аналитики.

## Принципы

- **Открытое и некоммерческое.** Весь код открыт под лицензией
  [GPL-3.0-or-later](#лицензия); рекламы, платных функций, подписок и закрытых
  частей нет и не будет ([ADR-0001](docs/adr/0001-open-source-non-commercial.md)).
- **Автономное.** Всё работает без сети, данные хранятся только на устройстве,
  аккаунтов и своего сервера нет. Сеть допускается только в интеграциях, которые
  пользователь включает сам: запросы к справочным сервисам, бэкап в подключённое
  им хранилище и т. п. (см. [Интеграции](#интеграции),
  [ADR-0002](docs/adr/0002-standalone-local-data.md)).

## Возможности

- 🤱 **Кормление грудью** — с выбором груди (левая/правая) и комментарием.
- 🧷 **Подгузники** — с типом содержимого: пописал / покакал / и то, и то.
- 😴 **Таймер сна** — «Уснул…» запускает таймер, «Проснулся» останавливает.
  Активный сон хранится в базе, поэтому таймер переживает перезапуск
  приложения и телефона.
- 💊 **Лекарства** — название и комментарий (доза, причина).
- ⚖️ **Вес** — в граммах (300–30000), в списке и на карточке ребёнка
  показывается как «4,35 кг».
- 👶 **Несколько детей** — у каждого ребёнка свои записи, таймер сна и сводка.
  Ребёнок добавляется через меню ⋮ → «Добавить ребёнка», переключение — чипами
  с именами вверху экрана (появляются, когда детей больше одного). Тап по
  карточке ребёнка — имя и дата рождения; возраст считается автоматически,
  текущий вес берётся из последнего взвешивания. Там же ребёнка можно удалить
  вместе с его записями (последнего — нельзя).
- ✏️ **Редактирование** — тап по любой записи открывает её на правку:
  можно поменять детали, комментарий, дату и время (у сна — начало и конец).
- Для новой записи можно указать, что событие было 5/15/30/60 минут назад.
- 📅 **История по дням** — по умолчанию показывается только сегодня;
  свайп влево/вправо листает дни с записями, тап по дате открывает
  селектор (в нём только дни, где есть данные, с количеством записей).
- Сводка показывает выбранный день: число кормлений (для сегодня — какая
  грудь была последней), подгузники с разбивкой, суммарный сон, лекарства.
- 📤 **Экспорт в CSV** и 📥 **импорт из CSV** через системный выбор файла
  (меню ⋮ в правом верхнем углу). Экспортируются все дети; импорт только
  добавляет записи, дубликаты пропускаются.
- 🎨 **Оформление** — светлая и тёмная тема, переключаются вместе с системной.
  Цвета приложения свои и одинаковы на всех телефонах: под обои (Material You)
  они не подстраиваются.

## Формат CSV

```csv
type,start,end,detail,note,child
PROFILE,2026-05-20 00:00:00,,,,Маша
PROFILE,,,,,Петя
FEEDING,2026-08-15 14:30:00,,LEFT,комментарий,Маша
DIAPER,2026-08-15 15:10:00,,WET,,Петя
SLEEP,2026-08-15 13:00:00,2026-08-15 14:20:00,,,Маша
MEDICINE,2026-08-15 09:00:00,,Витамин D,1 капля,Петя
WEIGHT,2026-08-15 10:00:00,,4350,после кормления,Маша
```

- `type`: `FEEDING` | `DIAPER` | `SLEEP` | `MEDICINE` | `WEIGHT`;
  служебная строка `PROFILE` описывает ребёнка: дата рождения в `start`
  (может быть пустой), имя в `child`
- `start`/`end`: локальное время `yyyy-MM-dd HH:mm:ss` (при импорте можно
  `T`-разделитель и время без секунд); `end` заполняется только для сна
- `detail`: грудь `LEFT`/`RIGHT`, подгузник `WET`/`DIRTY`/`MIXED`,
  название лекарства, вес в граммах (целое, 300–30000)
- `child`: имя ребёнка. При импорте ребёнок ищется по имени без учёта
  регистра; если его нет — создаётся. Файлы старых версий (без колонки
  `child`) импортируются к ребёнку, выбранному на экране
- Кодировка UTF-8 (файл экспортируется с BOM, чтобы Excel понимал кириллицу)
- При импорте дубликаты (полное совпадение всех полей у того же ребёнка)
  пропускаются; строки `SLEEP` с пустым `end` (незавершённый на момент
  экспорта сон) тоже пропускаются, чтобы не создать «фантомный» активный
  таймер; дата рождения из файла применяется, только если у ребёнка её нет
- Автобэкап Android отключён (`allowBackup=false`) — данные не попадают в
  облако Google; для переноса на новый телефон используйте CSV-экспорт

## Интеграции

Пока интеграций нет — приложение полностью офлайн. Каждая будущая интеграция
по умолчанию выключена и описывается здесь отдельным подразделом:

- что она делает;
- какие данные, куда и когда уходят с устройства;
- как включить и настроить (адреса, ключи и токены вводит пользователь, они
  хранятся только на телефоне);
- как отключить и что станет с уже переданными данными.

## Сборка

Нужны Android SDK и JDK 17 или новее — подойдёт встроенный в Android Studio;
недостающие платформы SDK Gradle скачает сам. Почему тулчейн такой —
[ADR-0006](docs/adr/0006-tech-stack-agp9.md).

```bash
# macOS; не нужно, если JAVA_HOME уже указывает на JDK 17+
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
./gradlew assembleRelease
```

APK: `app/build/outputs/apk/release/app-release.apk` (подписан debug-ключом —
для личной установки этого достаточно).

## Установка на телефон

1. Перекиньте APK на телефон (кабелем, AirDrop-аналогом и т.п.) и откройте его,
   разрешив установку из неизвестных источников, **или**
2. по кабелю: включите отладку по USB и выполните
   `adb install app/build/outputs/apk/release/app-release.apk`.

## Локальная отладка

Отладочная сборка ставится отдельным приложением «Дневник (debug)»
(`com.kid.babylog.debug`) со своей пустой базой. Основное приложение и его
записи она не трогает, поэтому её можно ставить и на свой телефон.

`scripts/dev.sh` сам берёт JDK из Android Studio, если в `JAVA_HOME` Java ниже 17,
так что настраивать для него JDK не нужно.

Всё запускается через `scripts/dev.sh` или в VS Code: Terminal → Run Task…
(⇧⌘B сразу собирает и запускает, ошибки Kotlin попадают в панель Problems).

| Команда                            | Что делает                                                              |
|------------------------------------|-------------------------------------------------------------------------|
| `scripts/dev.sh run`               | собрать debug, установить и открыть; эмулятор поднимется сам            |
| `scripts/dev.sh check`             | дизайн-токены, unit-тесты и debug-сборка (обязательная проверка)        |
| `scripts/dev.sh logcat`            | логи приложения (не теряются при перезапуске и падении)                 |
| `scripts/dev.sh db`                | скачать базу в `build/debug-db/babylog.db` (в VS Code — SQLite Viewer)  |
| `scripts/dev.sh screenshot`        | скриншот в `build/screenshots/`                                         |
| `scripts/dev.sh emulator` / `stop` | включить / выключить эмулятор                                           |

На телефон по USB: `ANDROID_SERIAL=<серийник из adb devices> scripts/dev.sh run`.

Брейкпоинты, Layout Inspector и Database Inspector — в Android Studio:
File → Open → папка проекта, затем Run → Debug 'app'. Нужна Android Studio
2026.2 или новее: проект собирается на AGP 9.4.

## Технологии

Kotlin, Jetpack Compose (Material 3), Room, минимум зависимостей.
Минимальная версия Android — 8.0 (API 26). Как устроен код —
[ADR-0007](docs/adr/0007-architecture.md). Оформление — своя тема Material 3
`BabyLogTheme`: цвета, шрифты, формы и отступы экраны берут только из неё
([ADR-0010](docs/adr/0010-design-system.md)).
